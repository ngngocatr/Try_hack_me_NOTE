# **Command Injection**
## **1. Discovering Command Injection**
Command injection xảy ra khi những ngôn ngữ lập trình cung cấp nhưng hàm gọi trực tiếp câu lệnh hệ điều hành, VD: **PHP** có `exec()`, `system()`, `shell_exec()`, và `passthru()`; **Python** thì có `subprocess`; `Node.js` có `child_process.exec()`\
Bản thân những hàm này không nguy hiểm, cái nguy hiểm ở đây là input được nhập vào mà không có bất kì kiểm tra nào 

### **A PHP Example**
```php
<?php
$songs = "/var/www/html/songs";                                    // 1

if (isset($_GET["title"])) {
    $title = $_GET["title"];                                       // 2

    $command = "grep $title /var/www/html/songtitle.txt";          // 3

    $search = exec($command);                                      // 4
    if ($search == "") {
        $return = "<p>The requested song</p><p> $title does </p><b>not</b><p> exist!</p>";
    } else {
        $return = "<p>The requested song</p><p> $title does </p><b>exist!</b>";
    }

    echo $return;
}
?>
```

- Biến `$songs` định nghĩa thư mục mà chứa tên của các file MP3 lưu trong hệ thống
- Đầu vào của người dùng được lấy bởi biến `$_GET` và lưu vào biến `$title`
- Biến `$title` được nối trực tiếp với câu lệnh hệ điều hành `grep`, không có bất kì kiểm tra nào ở đây
- Cuối cùng câu lệnh được thực thi bởi hàm `exec()` và web kiểm tra, trả về kết quả có tìm thấy hay không

Người dùng thông thường sẽ nhập đúng tên bài hát `?title=Yesterday` thì web sẽ thực thi câu lệnh 
```bash
grep Yesterday /var/www/html/songtitle.txt
```

Nhưng nếu một attacker nhập `?title=; cat /etc/passwd`, câu lệnh thực thi sẽ trở thành 

```bash
grep ; cat /etc/passwd /var/www/html/songtitle.txt
```

Lúc này kết quả trả về sẽ là nội dung của cả 2 file là `/etc/passwd` và `songtitle.txt`

### **A Python Example**
```python
import subprocess
from flask import Flask                                            # 1
app = Flask(__name__)

def execute_command(shell):                                        # 2
    return subprocess.Popen(shell, shell=True, stdout=subprocess.PIPE).stdout.read()

@app.route('/<shell>')                                             # 3
def command_server(shell):
    return execute_command(shell)
```

Chức năng này thực thi lệnh hệ điều hành thông qua hàm `execute_command()`

## **2. Exploiting Command Injection**
Ta có thể xác định được liệu rằng Command Injection có tồn tại không bằng cách quan sát hành động của một trang web\
Những payload quan trọng ở đây là những kí tự như `;`, `&`, `&&`, chúng là những kí tự cho phép nối nhiều câu lệnh hệ điều hành với nhau 

Có 2 thể loại đó chính là 
- **verbose command injection**: Web sẽ hiển thị kết quả của câu lện ra màn hình
- **blind command injection**: câu lệnh vẫn được thực thi trên hệ thống nhưng không trả lại bất kì kết quả trực tiếp nào lên trang web

### **Detecting Blind Command Injection**
Khi mà kết quả của câu lệnh không được nhìn thấy, ta cần xác nhận lỗ hổng bằng những dấu hiệu khác, payload phổ biến là dùng **time delay**\
Ví dụ: ta dùng câu lệnh ping để tăng thời gian câu lệnh thực thi, từ đó biết được rằng câu lệnh đã được thực thi 

```bash
ping -c 10 127.0.0.1
```

Attacker có dùng hàm `sleep(10)`\
Nếu có độ trễ khoảng 10s ta sẽ biết được câu lệnh đã được thực thi phía server

Có một cách khác là chuyển hướng output vào 1 file khác (*toán tử `>`*) rồi truy cập file đó bằng web; Ví dụ: `; whoami > /var/www/html/output.txt`
